# 국내 약 이름 검색 목록

건강보험심사평가원(HIRA)이 공공데이터포털에 배포한 실제 CSV 두 파일에서 생성한다. API 키, 로그인, 사용자 건강 기록은 사용하지 않는다. 앱에서는 네트워크 없이 제품명·성분명·품목기준코드를 검색한다. NIH 검색은 별도 버튼에서만 실행한다.

## 공식 출처와 범위

- [HIRA 약가마스터 의약품표준코드](https://www.data.go.kr/data/15067462/fileData.do): 2026-08-31 자료. 원본 `건강보험심사평가원_약가마스터_의약품표준코드_2026.08.csv`.
- [HIRA 약가마스터 의약품주성분](https://www.data.go.kr/data/15067461/fileData.do): 2026-11-05 자료. 원본 `건강보험심사평가원_약가마스터_의약품주성분 2026.11.csv`.
- 제공기관: 건강보험심사평가원. [공공누리 제1유형, 출처표시](https://www.kogl.or.kr/info/licenseType1.do). 본 앱의 가공본임을 명시하며 기관의 보증이나 추천을 의미하지 않는다.
- 원본 획득일: 2026-11-16. 정확한 다운로드 URL, SHA-256, 원본 바이트 수와 행 수는 `korean-drugs-source.json`에 기록한다.

이 목록은 누적 표준코드 매핑이다. 취소·급여삭제된 품목과 예전 제품명이 포함될 수 있다. 현재 허가, 유통, 처방, 급여 여부를 판단하는 자료가 아니며 치료 권고가 아니다. 식약처 전체 허가 목록을 내려받았다고 표시하지 않는다.

실제 제품 CSV에서 읽은 포장별 행은 309,889개다. 원문 포털의 행 수 메타데이터와 차이가 있어 가공본의 개수를 원본 파일에서 직접 계산했다. 전문의약품·일반의약품·전문희귀만 포함하고 원료·한약재·의약외품 및 품목기준코드가 없는 행은 제외한다. HTML 문자 참조만 해제하고 품목기준코드+제품명으로 포장 중복을 합쳤다. 서로 다른 과거 제품명은 유지한다. 91,324개의 제품명 기록을 한국어 유니코드 순서와 품목기준코드로 정렬했다.

성분은 제품 CSV의 `일반명코드(성분명코드)`와 성분 CSV의 `일반명코드`를 정확히 일치시켜 연결한다. 제품명이나 함량을 새로 조합하지 않는다. 성분 연결이 없는 제품은 제품명으로 검색한다. `korean-drugs.json`의 각 행은 `[품목기준코드, 원문 제품명, 연결된 원문 성분명]` 세 필드다. 용량·효능·가격·개인 기록은 포함하지 않는다.

## 재생성

Python 3 표준 라이브러리만 사용한다. npm 의존성을 추가하지 않는다.

```sh
python3 scripts/build-drug-catalog.py
```

공식 포털에서 공개 첨부 ID를 조회한 뒤 CSV를 내려받는다. 원본 자료의 기준일이 바뀌면 중단하므로 `SOURCES`의 날짜를 공식 페이지와 대조하고 갱신한다. 다운로드에 실패하거나 스키마가 달라지면 기존 가공본을 덮어쓰지 않는다. 원본은 CP949 또는 UTF-8 BOM을 처리한다.

이미 받은 동일한 공식 CSV로 재현하려면:

```sh
python3 scripts/build-drug-catalog.py --products /tmp/ongle-products.csv --ingredients /tmp/ongle-ingredients.csv
node tests/drugs.test.js
```

로컬 입력 옵션은 해당 공식 원본의 경로를 지정한다. 새 자료를 채택할 때 획득일과 이 문서의 범위·집계를 함께 갱신한다. 생성 파일에는 정렬된 데이터와 원본 해시가 포함되므로 동일 입력이면 동일 결과를 만든다.

## 검색과 검증

앱 렌더와 빈 검색에서는 데이터 파일을 가져오거나 색인을 만들지 않는다. 입력이 250ms 동안 멈춘 첫 검색에서 모듈 Web Worker를 생성하고, 무거운 JSON과 순수 검색 모듈은 그 Worker에서만 불러온다. 정규화된 검색 문자열과 bigram 역색인도 Worker에서 한 번 만든다. 각 요청의 증가하는 ID로 지연·역순 응답을 무시하며, 창을 닫으면 Worker와 타이머를 정리한다. 오류나 30초 시간 초과 시 직접 입력 안내를 보여 주고 다음 검색에서 다시 시작한다. 이후 검색은 가장 작은 후보 목록을 고른 뒤 모든 입력 단어가 일치하는지 확인한다. 정확한 제품명 접두어를 우선하고 최대 30개(호출자가 지정하면 최대 100개)를 반환한다. 띄어쓰기, 전각 문자, mg/밀리그램/밀리그람 표기를 정규화한다. `drugs.js`는 작은 출처 메타데이터·일정 함수·NIH 어댑터만 제공하고 `drugSearch.js`는 Worker와 순수 테스트에서만 참조한다. 빌드에는 별도 `drugSearchWorker-*.js`가 포함되므로 앱의 오프라인 캐시에 해당 출력 파일도 포함해야 한다. 조회는 국내 이름 검색이며 약의 선택·대체·복용을 추천하지 않는다. 직접 입력은 항상 가능하다.

테스트는 목록 규모·정렬·고유 식별자·출처·CSV 파싱, 제품명 및 성분명 검색, 크론병 관련 국내 브랜드/성분 이름의 검색 가능 여부를 확인한다. 검색 가능성 검증은 적응증이나 개별 환자에 대한 적합성을 주장하지 않는다.

## 확인한 다른 경로

- HIRA 공지의 약제급여목록 첨부: `https://www.hira.or.kr/bbsDummy.do?brdBltNo=12256&brdScnBltNo=4&pgmid=HIRAA020002000100`. 검색으로 공식 공지를 확인했으나 직접 연결은 타임아웃이었다.
- 식약처 의약품안전나라 공공데이터 안내는 기존 파일 다운로드 종료와 식의약 데이터 포털 CSV 이용을 안내한다: `https://nedrug.mfds.go.kr/pbp/CCBGA01/getList`.
- 식의약 데이터 포털 페이지에는 접근했지만 이 경로로 전체 허가 CSV를 확보한 것은 아니다. 실제로 확보한 HIRA 공개 CSV로만 가공본을 생성했다.
