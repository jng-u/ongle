# 온결 · 나의 건강 수첩

한국어 모바일 화면에서 매일 복약과 질병 경과를 기록하는 React 웹 앱입니다. 최초 실행 시 개인 수첩은 비어 있습니다. 가상의 예시 수첩은 별도 메모리에서 열리며 실제 기록이나 알림에 영향을 주지 않습니다.

## 실행

Node.js 22.12 이상을 사용합니다.

```sh
npm ci
npm run dev
```

실제 배포와 같은 코드, 서비스 워커 및 오프라인 동작을 확인하려면:

```sh
npm test
npm run build
npm run preview
```

미리보기 기본 주소는 http://127.0.0.1:4173 입니다. PORT와 HOST로 바꿀 수 있습니다. 다른 기기에서 설치·오프라인·기기 알림·암호화 백업을 쓸 때는 HTTPS로 서비스하세요. 미리보기용 Vite 서버 대신 빌드한 Worker나 독립 실행 서버를 사용합니다.

## 할 수 있는 일

- **오늘·복약 관리**: 한글 제품명·성분명·품목코드를 검색하거나 직접 입력하고 약마다 양, 메모, 복약 시간을 정합니다. 기본 시간 삭제·변경, 새 시간 추가와 약 재배정, 날짜별 체크를 지원합니다. 매일·요일별·격일(기준일 지정)·필요시 복용을 구분합니다. 필요시 복용은 여러 번 기록할 수 있고 예정 횟수에 포함되지 않습니다. 복용 당시의 약 이름·용량·시간대는 변경 후에도 실제 기록에서 볼 수 있습니다. 최초 등록일을 앞당겨 잘못 입력한 시작 날짜를 바로잡을 수 있습니다. 이후 변경 이력과 실제 복약 체크는 보존합니다.
- **기록 캘린더·증상 일기**: 월별 기록에서 날짜를 고르고 컨디션·메모에 더해 직접 이름 붙인 0~10 척도, 숫자, O/X 항목을 기록합니다. 통증·배변·혈변 항목도 선택할 수 있습니다. 응답하지 않은 값과 0/없음을 구분합니다.
- **진료·검사 이력**: 기존 일정에서 같은 병원의 다음 검사를 추가하고 주·개월 간격이나 날짜를 선택할 수 있습니다. 새 예약에는 과거 검사 결과나 완료 상태를 복사하지 않습니다.
- **검사 수치**: 같은 지표와 단위로만 추세를 그립니다. 검사 결과지의 참고범위, 미포함/포함 경계를 직접 설정할 수 있습니다. 일반 CRP와 대변 칼프로텍틴은 Mayo Clinic Laboratories 원문을 서버에서 확인한 뒤 제안합니다. 알부민·비타민 B12의 저장 자료도 있습니다. 참고범위가 개인의 치료 목표나 질병 활동도 판정은 아닙니다.
- **설정·백업**: 선택 시에만 기기 알림을 요청합니다. 안드로이드 앱은 OS에 복약 알람을 예약하므로 앱이 닫혀 있어도 기기 알림을 받을 수 있습니다. 정확한 알람 권한이 없으면 시각이 늦어질 수 있습니다. 설정에서 앱을 강제 종료했다면 다시 열어야 합니다. 웹 버전에서 브라우저 종료 중 알림이 필요하면 반복 일정과 알림이 든 ICS 파일을 기기 캘린더로 가져옵니다. 일정을 변경하거나 중단하면 전용 캘린더를 새 파일로 교체해야 합니다. 잠금 화면 알림은 기기·캘린더 앱 설정을 따릅니다.
- **진료용 요약**: 최근 30일·90일, 마지막으로 완료한 진료일부터, 또는 직접 고른 기간의 기록을 모아 인쇄하거나 PDF로 저장합니다. ‘복용 당시 약과 용량 포함’을 선택하면 실제 복용 내역도 함께 인쇄합니다.

## 저장 및 외부 연결

개인 기록은 이 원본(origin)의 브라우저 로컬 저장소에서만 읽고 씁니다. 사용자 계정이나 서버 저장소가 없습니다. 같은 브라우저 프로필을 여러 사람이 쓰면 같은 수첩을 열게 됩니다. 브라우저 데이터가 지워지면 기록도 사라질 수 있어 설정에서 백업을 제공합니다. 내보낸 파일은 비밀번호로 암호화되며, 비밀번호는 저장하거나 복구할 수 없습니다. 설정에는 마지막 파일 저장(Android) 또는 다운로드 요청(웹) 이후 변경된 기록 수가 표시됩니다. 백업 파일은 현재 기록을 바꾸지 않고 검증할 수 있습니다. 손상된 수첩도 정상 백업으로 복원할 수 있습니다. 복원 전 내용 수량과 차이를 보여 주고 명시적으로 교체한 경우만 기존 수첩을 바꿉니다.

국내 약 목록은 앱과 함께 제공하며 별도 키 없이 검색합니다. 공개 목록이므로 현재 허가·유통 여부를 보장하지 않습니다. [생성 과정과 원본 자료](src/data/DRUG-CATALOG.md)를 참고하세요. 영문 NIH 검색을 직접 누른 경우에만 검색어를 RxNorm으로 보냅니다. 검사 기준 API는 허용된 공개 지표 식별자만 받고 수치·메모 등 개인 기록은 받지 않습니다. 연결이나 원문 확인에 실패하면 실시간 결과로 표시하지 않습니다.

처음 온라인에서 로딩하고 서비스 워커가 설치되면 앱 화면·국내 약 검색을 오프라인에서 사용할 수 있습니다. 웹 기기 알림은 사용자가 허용한 HTTPS 환경 또는 localhost에서 동작합니다. 안드로이드 설치본의 예약 알림은 인터넷이나 캘린더가 필요하지 않습니다. 실시간 원문 조회와 NIH 영문 검색에는 인터넷이 필요합니다.

## 배포 구성

`dist/server/index.js`는 앱 정적 파일과 참고범위 API를 모두 제공하는 표준 Worker ESM입니다. `npm run preview`는 같은 Worker를 Node에서 실행합니다. `dist/client`만 정적 호스팅하면 기기 기록 기능과 오프라인 참고자료는 작동하지만 실시간 원문 조회용 `/api/lab-reference` 서버가 별도로 필요합니다. 기기 기록은 빌드, 소스 저장소 및 배포 파일에 포함되지 않습니다.

## 안드로이드 설치 파일

실행 중인 서버 주소 뒤에 `/android.apk`를 붙이거나 웹 수첩의 **설정·백업 → 안드로이드 앱**에서 내려받습니다. 포트포워딩으로 접속할 때는 휴대폰에서 접근 가능한 실제 주소를 사용하세요. APK는 안드로이드 8 이상과 최신 Android System WebView를 대상으로 합니다. 앱과 국내 약 목록이 함께 설치되어 설치 후 개인 기록에는 서버가 필요하지 않습니다. 브라우저 수첩과 앱 수첩은 별도로 저장되므로 기존 기록은 암호화 백업으로 이전하세요.

개발 환경에서 다시 만들려면 `bash android/build.sh`를 실행합니다. JDK 21, Android SDK Platform 36, Build Tools 36.0.0이 필요합니다. APK와 SHA-256 체크섬은 상위 releases 폴더에 생성합니다. 업데이트 배포 시 같은 서명 키를 사용하고 manifest의 versionCode를 높이세요. 키와 암호는 android/signing.local에 보관하며 APK·배포 압축본이나 소스 저장소에 포함하지 않습니다.

## 배포 전 확인

앱의 데이터·알림 규칙은 `npm test`로 검사합니다. `npm run build` 후 Playwright와 Chromium이 설치된 개발 환경에서 `npm run test:browser`를 실행하면 임시 로컬 서버와 빈 브라우저 프로필로 오프라인 약 검색, 긴 일기 백업, 손상 복원, 두 탭 편집, 실제 복약과 요약 인쇄를 확인합니다. Playwright가 다른 경로에 있다면 `PLAYWRIGHT_MODULE`에 해당 모듈의 절대 경로를 지정하세요. 개인 기록이나 실행 중인 서버는 사용하지 않습니다.
